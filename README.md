# Баланс питания и активности

Адаптивное HTML5-приложение для расчёта пищевой ценности, энергозатрат и дневного баланса калорий. Работает целиком в браузере и не требует сервера, Python или установки зависимостей.

## Возможности

- расчёт калорий, белков, жиров и углеводов для порции;
- публичный каталог из 1 432 проверенных продуктов и блюд с поиском и древом «группа → подгруппа → продукт»;
- накопительный дневной итог и ручной ввод калорий;
- трекер воды с дневной нормой, заполняющейся бутылкой и отметками превышения по 250 мл;
- профиль пользователя с весом, ростом, возрастом и полом;
- готовый профиль **Eni**: 83 кг, 178 см, 32 года;
- готовый профиль **Бусинка**: женщина, 63 кг, 174 см, 35 лет;
- расчёт базового обмена за время покоя;
- расчёт расхода для шагов, кардио и силовых тренировок;
- индикатор дефицита или профицита калорий;
- архив по датам в локальном хранилище браузера;
- график баланса за неделю, месяц, 3 или 6 месяцев;
- переход к конкретному дню нажатием на его столбец в графике;
- импорт архива и экспорт выбранного дня через Google Drive;
- экспорт полной резервной копии профиля и архива;
- обнуление локальных данных за выбранный диапазон дат без их повторного автоматического добавления в график;
- адаптивный интерфейс для компьютера, планшета и телефона.

## Запуск

Откройте `index.html` в браузере. Для корректной проверки импорта старого JSON лучше запустить локальный сервер:

```powershell
python -m http.server 8765 --bind 127.0.0.1
```

Затем откройте `http://127.0.0.1:8765/`. Это основной локальный адрес проекта.

## Синхронизация с Google Drive

Для проекта создана папка **«Баланс питания и активности — данные»**. Кнопка **Экспорт** создаёт или обновляет в ней файл `Меню и активность YYYY-MM-DD.json` за выбранную дату. Кнопка **Импорт** читает JSON-файлы из папки, сохраняет корректные записи в локальный архив и обновляет данные графика.

Если выбран профиль **Eni** или **Бусинка**, импорт и экспорт работают с одноимённой отдельной подпапкой. Для Eni автоматически применяется мужской пол, для Бусинки — женский. При ручном вводе параметров файлы остаются в общей папке. Google Picker может один раз попросить предоставить приложению доступ к каждой из этих папок.

Настройки подключения хранятся в `google-drive-config.js`. Перед публикацией ограничьте их в Google Cloud доменом GitHub Pages и нужными API; значения конфигурации не должны попадать в документацию или сообщения.

В Google Cloud должны быть включены **Google Drive API** и **Google Picker API**. Для веб-приложения добавьте разрешённые JavaScript origins:

```text
http://127.0.0.1:8765
https://ИМЯ-ПОЛЬЗОВАТЕЛЯ.github.io
```

Приложение использует ограниченный доступ `drive.file`. При первом подключении Google Picker попросит предоставить доступ к проектной папке; токен хранится только в памяти вкладки и не записывается в `localStorage` или репозиторий.

Кнопка **«Обнулить период»** в верхней панели удаляет локальные дневные записи между датами «от» и «до» включительно. Диапазон помечается очищенным, поэтому старые JSON-файлы, опубликованные вместе с сайтом, не восстановятся автоматически. Файлы Google Drive эта операция не удаляет; явный импорт с Drive может восстановить их по запросу пользователя.

## Хранение данных

GitHub Pages — статический хостинг, поэтому приложение хранит профиль и дневные записи в `localStorage` текущего браузера. Данные не отправляются на сервер и не синхронизируются между устройствами.

В Google Drive выбранный день сохраняется в прежнем формате:

```json
{
  "date": "2026-08-12",
  "menu": {
    "totals": {
      "calories": 1235.15,
      "proteins": 87.39,
      "fats": 59.435,
      "carbs": 88.41
    }
  },
  "activity": {
    "burned_calories": 1685
  },
  "water": {
    "goal_ml": 2000,
    "consumed_ml": 1750
  }
}
```

Кнопка **Скачать весь архив** по-прежнему создаёт локальную резервную копию всех дат вместе с профилем.

При первом открытии приложение также пытается прочитать старый JSON за текущую дату из папки `График меню и активности`, если такой файл опубликован вместе с сайтом.

## Каталог продуктов

Каталог формируется скриптом `food-data-sources/build_food_database.py` из USDA FoodData Central, Anses-CIQUAL 2025, немецкой базы BLS 4.0, проверенных региональных рецептур и разрешённой к использованию [таблицы школы №65](https://xn--65-6kc3bfr2e.xn--80acgfbsl1azdqr.xn--p1ai/?section_id=36). В опубликованной сборке 387 основных и 1 035 расширенных позиций. Таблица школы подключается последней и не заменяет прежние строки. Брендовые продукты USDA и строки без однозначного русского названия исключены. Отображаемые названия собираются только из контролируемого русского словаря: машинная транслитерация и автоматические уточнения больше не используются. Точные русские дубли удаляются, а КБЖУ проходят проверку диапазонов и энергетической согласованности.

Публичный `food-database.js` собран с параметром `--public`: источники без подтверждённого права на распространение в репозиторий не включаются.

Отдельно добавлены 235 блюд русской, кавказской, тайской, узбекской, грузинской, японской, индийской, таджикской и итальянской кухни: супы, салаты, выпечка, пельмени, вареники, хинкали, хачапури, долма, люля-кебаб, паста, пицца, супы-пюре, ризотто, плов, лагман, манты, хачапури, рамен, суши, карри, бирьяни, дал, том ям, пад тай и десерты. Для региональных блюд указаны средние значения на 100 г по типовой рецептуре; конкретное блюдо может отличаться по составу. Исходное название и источник каждой позиции сохраняются в карточке. Проверка каталога запускается командой `python food-data-sources/audit_food_database.py`.
- Шаги: `шаги × вес × 0,00050769`.
- Спорт: `MET × 3,5 × вес × минуты / 200`.
- BMR для мужчины: `88,36 + 13,4 × вес + 4,8 × рост − 5,7 × возраст`.
- BMR для женщины: `447,6 + 9,2 × вес + 3,1 × рост − 4,3 × возраст`.
- Расход в покое: `BMR × длительность в часах / 24`.

Файл `app.pyw` остаётся локально как исходная настольная версия для справки. Опубликованный репозиторий использует только веб-файлы.
